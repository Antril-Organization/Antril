Antril (`.ant`) is a general-purpose, object-oriented language that compiles ahead of time. It aims for the productivity of a high-level language: classes, records, generics, pattern matching, `async`/`await` and reactive values. You still keep low-level control when you need it: you pick the memory model per project, use references checked by a borrow checker, regions, fixed buffers and direct calls into C libraries.

Antril is compiled by [Larva](https://github.com/Antril-Organization/Larva). This repository holds the **Antril language pack**, the part Larva loads to compile, check and display Antril code, together with its tests and the VS Code extension.

## A first look

```antril
import System;

into namespace People
{
    public record class Person
    {
        public:
            str Name;
            i32 Age;
            new(str Name, i32 Age);
    }

    Main()
    {
        Person ana = new Person("Ana", 31);
        Person older = ana with { Age = 32 };
        Console.WriteLine(ana);
        Console.WriteLine(ana == new Person("Ana", 31));
        if (ana is Person(var name, > 30))
            Console.WriteLine(name + " is over 30");
    }
}
```

```console
$ larva run
Person { Name = Ana, Age = 31 }
true
Ana is over 30
```

## Getting started

The Antril pack ships with Larva's installers. Install Larva and check that the language is there:

```shell
larva languages
```

Create a program and run it:

```shell
larva new Console-App Hello --lang antril
cd Hello
larva run
```

From the same project, `larva build` makes a native executable, `larva build --target wasm-llvm -o app.js` makes WebAssembly, and `larva build --check` only type-checks.

For VS Code, install the **Antril** extension. It installs the **Larva** extension with it, which brings errors as you type, completion, navigation and the build commands.

## The language at a glance

| Area | What Antril gives you |
| --- | --- |
| **Types** | Classes with one base and many interfaces, default interface methods, `final` and `base` classes, value types, `record` classes that compare by content, enums backed by values, tuples. |
| **Generics** | Generic types and methods with constraints, shared or specialized per type argument, as the project chooses. |
| **Patterns** | `is` and `switch` patterns: type, positional, property, relational and `var` patterns, plus `with` expressions on records. |
| **Errors** | Exceptions with `try`/`catch`/`finally`, and declared exception types. |
| **Memory** | Each project chooses its model: tracing GC, reference counting, arenas, manual memory, or a custom collector. On top of that: destructors, `region { }` blocks, `&T` and `&mut T` references with a borrow checker, `fixed` buffers, and `unsafe` pointers where a project allows them. |
| **Async** | `async`/`await` compiled to state machines, iterators, and streams. |
| **Reactive code** | `reactive` fields, `computed` values, `reacts` methods and `effect` blocks that run again when the values they read change, with batching. |
| **Interop** | Calls into C libraries through bindings generated by `larva bind`, with structs, unions, callbacks and constants. |
| **Attributes** | Declared with the `attribute` keyword, on types, members, parameters and enum members. |

Reactive state, for example, is part of the language:

```antril
import System;
import System.Reactive;

into namespace Ui
{
    public class Cart
    {
        public:
            reactive i32 items = 0;
            reactive f64 price = 2.5;
            computed f64 Total => items * price;
    }

    Main()
    {
        Cart cart = new Cart();
        Effect shown = effect { Console.WriteLine("total: " + cart.Total); }; // total: 0
        cart.items = 2;                                          // total: 5
        Reactive.Batch(() => { cart.items = 3; cart.price = 4.0; }); // total: 12, once
        shown.Dispose();
    }
}
```

## Building from source

Antril builds against Larva's libraries. Clone Larva next to this repository, or point the `LarvaRoot` property at your Larva working copy. The build tools you need are the ones listed in [Larva's README](https://github.com/Antril-Organization/Larva#building-from-source).

```text
repos/
├── Larva/
└── Antril/
```

```shell
dotnet build Antril.slnx
dotnet test --project tests/Antril.Tests
```

Each build also writes the pack to `artifacts/pack/Antril`. Point a Larva working copy at that folder to use your build:

```shell
# Windows
set LARVA_LANGUAGES=C:\path\to\Antril\artifacts\pack
dotnet ..\Larva\Larva.Cli\bin\Debug\net10.0\larva.dll languages

# Linux, macOS
export LARVA_LANGUAGES=/path/to/Antril/artifacts/pack
dotnet ../Larva/Larva.Cli/bin/Debug/net10.0/larva.dll languages
```

### Packaging for Larva's installers

`tools/publish-pack.ps1` (Windows) or `tools/publish-pack.sh` (Linux, macOS) compile the pack natively into `artifacts/languages/Antril`. Larva's installer build takes it from there by default, then signs it and ships it in `Languages/Antril`.

## Repository layout

| Folder | Contents |
| --- | --- |
| `src/Antril` | The language pack, in three parts: the frontend, which turns Antril source into Larva HIR; the view, which writes HIR back as Antril for decompiled types; and the editor services. |
| `tests/Antril.Tests` | The test suite. It covers the frontend, the editor services, the pack loaded by `larva` (`build`, `lsp`, `bind --profile`), and Antril programs run on every Larva back end. It also covers Larva's standard library, which is written in Antril. |
| `vscode-antril` | The VS Code extension for `.ant` files: syntax highlighting, snippets, file icons and semantic colors. |
| `tools` | Scripts that publish the native pack for Larva's installers. |

Larva's standard library (`System.Core`, `System.Bindings`) is written in Antril, but it belongs to Larva. It lives in [Larva's `Library/`](https://github.com/Antril-Organization/Larva/tree/master/Library), and Larva's installer compiles it with this pack.

## Contributing

Issues and pull requests are welcome. Before you open a pull request:

1. Run the test suite (`dotnet test --project tests/Antril.Tests`). Every test must pass.
2. Add a test for each language change, ideally a whole program run on the back ends.
3. Keep each pull request focused on one change, and describe the change and why it is needed.
